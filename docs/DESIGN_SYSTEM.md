# HermesCRM Workbench design system

The native pane and standalone web surface share a restrained Workbench design:
cool canvas, flat panels, underlined navigation, blue actions and a neutral sans
text hierarchy. This is a presentation update, not a change to data ownership,
permissions, model access or execution guarantees.

## Tokens and interaction rules

| Role | Light | Dark |
| --- | --- | --- |
| Canvas | #F5F7FA | #101216 |
| Panel | #FFFFFF | #181B21 |
| Primary text | #18191B | #F2F4F8 |
| Secondary text | #5F636B | #D6DCE5 |
| Divider | #D8DFE8 | #343B46 |
| Input boundary | #8C929B | #697586 |
| Primary action | #1F4DFF | #365DEB |
| Link / keyboard focus | #1F4DFF | #8FAAFF |
| Selection | #EAF0FE | #243254 |

- Primary, secondary, status and link text/background pairs are checked at a
  minimum 4.5:1 contrast. The native dark secondary role is full-opacity #D6DCE5;
  disabled-control colors are not reused for active metadata.
- Titles use 28/32, sections and primary navigation 18/24, body 14/21, secondary text 13/18 and short
  labels 12/16 pixels. Primary navigation occupies its own row beneath the brand. Narrow titles use 24/28. Data uses tabular numerals.
- Four-pixel corners and a 4/8/12/16/24/32 spacing scale apply to cards,
  controls, forms and drawers. Circular chart geometry is an intentional exception.
- Native controls are at least 36 pixels high, 44 with a coarse pointer.
  Focus indicators are always available. Reduced-motion and forced-color
  styles are included. No hover-only actions, gradients, blur or card lifting.
- Tables and pipeline boards may scroll horizontally within named regions;
  ordinary page and drawer content should not require sideways scrolling.
- Native light/dark follows the host's root `dark` class, verified against host
  source 2bd378ed1b8d6bf2192cb26e0a55ff3091e6bd19. Standalone follows the OS/browser
  preference. Neither changes Hermes settings or colors outside the CRM pane.

## Applied surfaces

| Area | Application |
| --- | --- |
| Shared shell | Compact wordmark, underlined tabs, page title, scope, actions, help, footer disclosure |
| Overview | Consistent KPI cards, compact attention strip, stage donut and readable clickable summaries, Upcoming Tasks with contact/assignment context, activity rows |
| Contacts | Aligned filters, labeled table columns, alternating row surfaces, blue bold name links, identity/company/type/linked stages, pagination |
| Pipeline | Flat stage columns, visible zero counts, scannable opportunity cards and exact cent-aware currency |
| Tasks | Follow-ups first, readable state labels, saved coverage evidence in expandable detail |
| Activity | Flat scan-friendly rows, consistent metadata and empty state |
| Contact/deal/task details | Identity/actions, related records, grouped properties, timeline, metadata disclosure |
| Create/edit | Consistent grouped labels, field hints, validation, padded scroll body and pinned actions |
| Agent work | Forms, operation review, scope warnings, saved evidence and unknown-outcome notices |
| Reporting | Shared dashboard cards, structured report builder/filters, table/chart results and keyboard drilldowns |
| Contact log | Structured forms, provenance disclosure, clear empty/loading/error and approval states |
| Customization | Stage/field lists, grouped definition editor, descriptions and preserved archive/type constraints |
| Protection | Key-availability state, note fields, encrypted export review and retained privacy warnings |
| Contact CSV | Padded mapping/preview body, row review, export controls and separate footer |
| Standalone | Five existing routes, dashboard/list/board/detail/form/dialog and status states; not native feature parity |

No data, audit history or synthetic-record provenance is removed for appearance.
Technical evidence is still present in labeled disclosures. Readiness, unknown
outcomes, consent and the difference between saving, scheduling and executing
remain explicit. Whole-dollar values omit trailing .00; nonzero cents are shown.

## Wordmark and licensing

The original HERMESCRM outlined wordmark uses Libre Bodoni Bold under SIL OFL 1.1,
with optical width/tracking adjustments. It is not a copied Hermes logo and does
not bundle the commercial Collapse typeface used by the reference host. No font
or image is requested from the network at runtime. The SVG uses currentColor and
has an accessible HermesCRM name. Use 24 pixels high by default, at least 20.

The SVG, original OFL notice and provenance are in `assets/brand/`. The standalone
package retains the notice and provenance in its static assets. These notices
are separate from the MIT license covering project code. No endorsement is implied.

## Implementation and verification

`desktop/design-system.css` is the native source of truth. Run
`python scripts/build_design_system.py` to inline it into the single-module plugin.
The wordmark component is generated by `scripts/build_wordmark_component.py`.
Existing panel generators continue to own their marked source sections.

`tests/native_workbench.mjs` and `tests/standalone_workbench.cjs` check token,
contrast, accessibility-style and asset contracts. Existing React/VM suites test
routing, profile switches, stale forms, filters, chart drilldowns, repeated
submission, idempotency and unknown outcomes. These are not substitutes for
browser rendering or assistive-technology testing.

Visual verification and remaining limits are recorded in the verification report.
Future polish work includes physical-host keyboard/screen-reader testing,
user zoom/high-contrast validation, more long/multilingual content, and
large-dataset density. Do not claim a general accessibility certification.
